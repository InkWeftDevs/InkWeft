# 真实格式影子同步合同（v45）

这是隔离实验，应用没有启用真实资料库同步的入口。`ShadowReplica.open` 只在可调试构建里创建 `cache/shadow-sync/<UUID>/replica.db`，不能接收任意数据库路径；重新打开必须核对服务器、签发者、账号、资料库和设备绑定。

## 编码与闭包

`inkweft.shadow-rows.v1` 传输按已编译作者 schema 拆分的行增量。行身份由表序号和主键摘要确定，保留全部正式列；二进制列原样 Base64，包含实际 IWO9、笔迹材质、局部擦除、JPEG、导图、来源快照和文档块。schema 指纹进入 AES-256-GCM 的关联数据；未知格式、列数、schema 或缺失密钥阻断整批。

每次操作有独立 UUID、96 位随机 nonce 和密钥版本。密钥由实验调用方提供，独立于整库备份密钥。载荷加密后持久化发件箱；源数据变更和发件箱处于同一 Room/SQLite 事务。未经过该事务的作者修改会阻断后续接收，不静默覆盖。此实现不扫描主库，也不发送凭据、缓存、未封笔检查点或运行任务。

接收后先保存版本头，再在同一个事务中重建隔离库的已选择版本，并复用正式库校验器检查字段、实际编解码、引用和 PDF。作者数据、已应用操作摘要和游标共同提交；故障回滚全部修改。依赖缺失不能通过删除用户摘要或复活回收页面修补。现有回收状态及来源快照原样保留。

## 冲突与持久服务

每行有因果父版本。并发人工版本全部保留，继续显示该客户端原先选择的可用人工头；派生版本不能替代人工头。不使用时间戳或最后上传者覆盖。当前没有通用冲突选择 UI；跨多行的不兼容组合会校验失败、保留旧状态并等待显式处置。不得把不同客户端暂时显示不同冲突头称为已收敛。

`backup-server/shadow.py` 使用独立 SQLite 文件、序列、操作摘要和游标。复用服务器账号/设备会话及资料库授权；普通服务默认不挂载影子路由，合成 fixture 明确启用。设备撤销后旧会话不能拉取；未知游标返回明确冲突，不自动重置为零。发件箱只有拉回本操作且接收已提交后才能删除，未知响应重试同一操作。

## 明确上限

实验最多 2048 行、8 MiB 作者编码、1 MiB 单次加密操作；单个二进制列最多 1 MiB，每行最多 32 个并发头。Relay 单账号 16 MiB、全局 64 MiB。大资料库、分批附件流、自动快照重建、密钥分发产品流程、跨类型冲突选择 UI 尚未实现；超过上限直接阻断。

客户端为两个本机隔离 Room 库；持久 Relay 是独立网络进程。测试命令与结果收录在当前版本验证记录，不能把旧内存 JSON 模型的通过数累加到这里。
