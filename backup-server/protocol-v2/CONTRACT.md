# 8 GiB 加密云备份协议设计

状态：Go 服务与 Android v2 已完成本地进程、600 MiB/2 GiB/8 GiB 实际传输及分项验收，结果见 Android 本轮验证报告。Docker 按用户安排留待云端执行，物理设备另测。目标经用户确认：单份完整资料库明文最多 8 GiB。部署入口与 schema 重建规则见 GO-DEPLOYMENT.md；尚未部署公网。

## 容量与发现

- 完整资料库归档继续沿用 `LibraryArchive` v2 的 8 GiB 边界。加密文件采用独立 `IWBK2` 头，头内 `format=2`，清晰区分云备份协议与资料库归档格式。旧任务继续由 v1 执行器处理；v2 任务不交给旧包读取。早期版本不叠加旧包读取 v2 的适配层。
- 继续使用 AES-256-GCM：每个加密块明文 256 KiB，12-byte nonce 为随机 8-byte 前缀加 32-bit 块序号；同一数据密钥只对应一个不可变备份身份。AAD 绑定头摘要和序号，恢复密钥独立包裹随机数据密钥。8 GiB 最多 32,768 个加密块，远低于序号溢出边界；重试发送已生成密文，不能用同一 nonce 重新加密变化内容。
- 密文最大值为 `plain + ceil(plain/262144)*20 + 4106`，以 64-bit 算术验算。网络块继续 1 MiB，最多 8,193 块。完整 SHA-256 列表约 550 KiB，仍在单请求 1 MiB 预算内，故无需增加分段清单协议。最终块长度必须准确，序号不能重复/越界，总密文长度与清单相符。
- `/v2/identity` 返回稳定 server/issuer、协议 2、最大明文/密文/网络块/清单数，以及功能 `resume-upload`、`resume-download`、`download-lease`。登录后容量接口返回本账户已占用、预留、可用配额及服务端物理余量；发现和身份校验在创建一致副本之前完成。旧 v1 任务继续在原服务器处理，新建备份要求 v2；服务器尚未支持时直接提示协议不匹配，不先生成 8 GiB 临时副本。

## 配额与服务端持久性

账户额度与全站额度必须可配置。建议初始账户 32 GiB、全站 128 GiB、每账户最多 4 个待上传、每库最多 10 个可用/待发布版本；Go 默认采用这些额度，可用环境变量调整。额度至少容纳一个最大密文。不能只把现有 `LIBRARY_LIMIT` 常数增大，因为当前账户 2 GiB、全站 8 GiB 根本容不下最大份额。

v2 操作表增加明确 `cipher_bytes`、创建/最后进度时间、状态、清单摘要和清单；SQLite 用 `BEGIN IMMEDIATE` 原子核对所有账户/全站的 `PENDING + PUBLISHED + DELETING` 字节，先预留整份份额，再接收第一块。重复 begin 返回原状态和摘要，不重复预留；相同身份不同内容返回 409。还要检查文件系统实际余量和安全水位，不能以逻辑配额代替磁盘容量。

密文存放在库/操作私有目录的不可变分块文件，而非把 8 GiB 塞进单个 SQLite BLOB。每块按 1 MiB 上限读取、验长度和 SHA，写 `.partial`、fsync，再同目录原子发布；文件和目录持久后才写数据库块回执。崩溃恢复只接纳已校验的完整文件，未登记文件可重新核验登记或清理。SQLite 和文件不同步时宁可重传，不能把未落盘块报告为已收到。

PENDING / PUBLISHED / DELETING / DELETED / EXPIRED 状态与操作摘要保持永久幂等身份。发布先核对块清单与总长度，再在写事务外逐件复核文件长度与 SHA-256，每次约 2 秒后把已核验块数持久化。未核验完返回 `PENDING` 与 `verified`，客户端继续按同一 operation 请求发布；全部核验后才在短事务改为 `PUBLISHED`。进程重启保留进度，发布响应丢失先查询原回执。7 天无进度的 pending 可过期；每次成功新增块刷新最后进度。同一块重试、发布检查不无限延长空闲期限。过期/删除保留身份和摘要，重试不能复活原操作；新备份使用新 operation。

删除与发布在同一写事务串行化。payload 删除完成后才释放物理份额；失败进入 DELETING 并保留预留，重启继续。清理不得按文件年龄直接删除已发布或下载租约保护的块。用户删除版本仍要求显式操作，协议扩容本身不触发删除旧版本。

## 上传、断点和后台预算

沿用不可变本地密文、原子队列指针、账户/设备/服务器/资料库绑定。v2 队列记协议、清单摘要、密文文件和原 operation；登录切换时不能沿用别人的任务。暂停、重启和令牌过期都保留本地队列。续传获取权威 received 集合，只通过文件 seek 读取缺失块，避免每次从第 0 块重新读取并哈希整份 8 GiB 文件。

将现有 2 分钟整任务截止改为可恢复的分片运行预算：每个后台运行片最多约 55 秒，单 HTTP 请求仍有截止；进度写回后重新调度，用户暂停立即停止。总任务按最后进度与服务器 pending 有效期判断，不用 2 分钟截止宣布大备份失败。429 的 Retry-After 不提前重试，网络/电量/前台书写限制沿用。收到未知发布结果先核对原回执，再上传缺块或发布。

## 恢复与空间预算

下载先请求绑定账户/资料库/版本/清单摘要的租约；租约内清单及密文不可变，版本删除进入 DELETING 并等待活动租约结束。租约刷新只延长同一已存在版本，不允许过期版本复活。断线后重新登录、重新绑定并核对同一清单；服务器无该版本时停止，保留明确错误。

本地下载目录用稳定任务身份。逐块验 SHA、写正确 offset、fsync 后再原子更新 received 位图。恢复时复核最后登记块；丢失/损坏块撤销位图并重下。下载完成核对总字节与全部块，然后逐 GCM 块认证/解密到独立归档文件。错误密钥、截断、错序或篡改不能产生可导入的完成归档。

恢复预检分别计算密文下载、明文归档、隔离 staging 数据库/原件、最终库新增内容和 32 MiB 水位。不能沿用 `cipherBytes*2` 假定两份足够。每个阶段都核对真实空间，已验证且不再需要的前阶段材料按事务边界释放；有活动读取租约的不删除。隔离校验全部作者引用闭包；确认后按现有 restore 契约原子导入，身份冲突停止，绝不覆盖用户资料。

## 实施门槛与验收

上线前必须同时完成服务端 v2、Android 队列/后台分片/下载恢复、密文 v2 实现、迁移/协议发现和部署容量配置。需要实际 600 MiB、2 GiB、8 GiB 资料库端到端上传与空库恢复，逐件摘要一致；模拟容量验算不能替代这些执行。

必须注入：块文件落盘前/后、回执前/后、publish/delete 响应丢失、分段发布进度落盘后进程退出、下载位图写入前/后、磁盘满、错误密钥、令牌过期、同账户并发超配额、另一账户串读、删除遇到活动下载。不同版本/设备记录独立身份与结果。真机用例见 Android `DEVICE-TEST-CHECKLIST.md`；当前 CLOUD91-* 为待测。

`verify_design.py` 只验证 64-bit 容量、网络块/清单预算、缺块随机读取计划以及完整恢复空间下限，不把这些验算标为服务端或真机通过。
