# 笔刷方案 B1 与墨织 v24 的差距评审

评审日期：2026-09-27。基线：`e7cc686eb5fd41b521884a94a36686dee48cd975`，应用 `0.0.24-visible-editing`；开始评审时工作区干净。

输入为用户提供的 `BRUSH-DESIGN.md`。本轮只做代码、依赖接口和文档核对，不实现笔刷、不生成安装包、不操作平板。文档中的 CONTRACT、TARGET、CANDIDATE 分别按行为要求、待验证目标、候选参数理解；不把建议参数或历史 v24 测试当作 B1 已验收。

## 结论

**方向可采纳，但应先补齐外观保存和渲染接点，再交付铅笔。** 圆珠笔、即时预设、逐笔参数冻结、局部擦除和缩略图有可复用基础；铅笔材质、逐笔不可变配方、真正试写区尚未实现。钢笔无压力回退与方案存在明确行为冲突。整体是跨输入、渲染和存储的中等以上改动，不能按“再加一种笔”的小改动估计。

建议调整四处：① 先验证现有 alpha09 材质接口，不默认升级依赖；② 将跨页临时笔迹与分段保存列为首批接点；③ 把“导出”区分为已有可编辑内容副本和未完成的视觉导出后端；④ 旧数据只明确冻结到当前 v24 基线，不承诺恢复未保存过的历代外观。

## 优先处理的差距

### 1. 先保存外观，再增加更多可调参数

`InkStroke` 当前保存类型、颜色、宽度、输入工具、采样、坐标形式与擦除遮罩，没有 recipe、输入调理版本、纹理种子、材质变换或资源摘要。v24 的参数已在落笔时冻结，但冻结范围仅覆盖现有字段。若只给收藏笔增加灵敏度滑块，再让历史渲染去读当前设置，就会破坏 B10。

本项目允许早期破坏性更新，因此不建议搭建庞大的历史兼容框架。可先把一个小型不可变配方值写入新版本笔迹编码，按规范化内容计算摘要；需要时再去重共享，不必首期建立复杂的配方数据库。读旧笔迹时采用明确的 `legacy-v24` 解释，不依赖可变收藏。

**边界：不能恢复未保存的历史外观。** 老记录没有创建时的渲染配方，无法仅从样本推断究竟应采用 v23 或更早算法；v24 已明确采用更新后的渲染规则。B1 可以保证此后稳定，不能宣称还原所有旧版外观。

笔种当前以 enum ordinal 写入，未知值会明确报错，没有静默退回钢笔。新增铅笔应使用新格式的固定 wire ID；若短期追加枚举，也必须保留现有0—4含义并明确解码版本。内容副本、备份、页面复制、摘录快照都要携带完整外观信息，而不只增加主画布字段。[编码入口](E:/Inkweft/recon/android/core-domain/src/main/kotlin/org/inkweft/core/InkModels.kt:71)

### 2. 统一的渲染入口目前有一个跨页例外

实时原页、历史笔迹和参数样笔共用 InkBrushes，书库／页面缩略图也使用 InkCanvasView，这是可复用基础。但相邻页的 `seamDraft` 直接用普通 Paint 绘制固定宽度路径，未应用笔型压力与材质。[临时跨页绘制](E:/Inkweft/recon/android/app/src/main/java/org/inkweft/app/InkCanvasView.kt:184)

`ContinuousInk.split()` 把一次连续手势拆成多个新 ID，平移到页面局部坐标。铅笔若按新 ID 重新取种子，或按分段边界重新定位纹理，会在接缝换花纹；逐段重新启动压力滤波／笔锋也可能产生接缝。[跨页分段](E:/Inkweft/recon/android/core-domain/src/main/kotlin/org/inkweft/core/ContinuousInk.kt:9)

建议一次落笔冻结配方、种子、纹理原点及手势连续性信息；分段共享它们，只改变页面变换。纹理原点不能用每帧变化的包围盒左上角计算。B1 方案应新增跨页验收，覆盖实时、抬笔、反向跨页、擦除、复制与重开。

### 3. 输入合同有基础，但还没有完整调理层

已做到：区分 STYLUS／TOUCH／MOUSE，缺轴用−1，落笔冻结轴范围与笔种，后续通过活动 pointer ID 找索引，读取历史采样；不会按每笔压力极值自动拉满。保存的是已按设备范围归一化、裁剪到0—1的作者压力，不能称为未处理的硬件原值。[输入入口](E:/Inkweft/recon/android/app/src/main/java/org/inkweft/app/InkCanvasView.kt:202)

仍有缺口：

- 没有压力调理合同版本、可观测轴变化状态或明确的短暂丢轴策略；现在能力诊断主要表示设备声明该轴存在。
- 同位置、同时间戳的后续样本在 live append 中直接返回，可能丢掉更新后的压力／倾斜；历史重放合并却保留最后轴值，规则不统一。[去重位置](E:/Inkweft/recon/android/app/src/main/java/org/inkweft/app/InkCanvasView.kt:243)
- 活动笔已经建立后使用正确索引；但落笔入口只在 ACTION_DOWN，尚不能据此认定“手指先接触、笔随后作为另一 pointer 加入”已支持。应补混合输入场景，不能笼统说代码永远只读 pointer 0。
- 没有方案建议的时间型压力平滑和有限起收笔策略；这两项需要测短点、短划及抬笔零压力，而不是直接照填8—16ms。
- 倾斜、方位虽已存储，但尚未用于铅笔铺色；还需要验证其相对纸面方向与视图变换，不能声称已支持笔杆旋转。

建议让 PressurePolicy 输出派生渲染值，原作者样本保持已有含义；缺压等价值、速度辅助、短暂缺值处理都要随配方冻结。真实压力0继续作为有效值。

### 4. 钢笔模型应选定，再校准参数

同方向、同速度下，v24 理论宽度乘数在压力0.1与0.9之间的比值约 **1.513**；方案候选 `r=0.40、q=0.90` 的比值约 **1.989**。这是公式计算，不是实机像素测量。既有测试只要求钢笔在0.1与0.8下比值大于1.2，不能当作 B1 的≥1.7目标已通过。

当前钢笔压力曲线只在 PenKinds 做一次幂映射，BrushBehavior 再做线性宽度映射，没有再次叠加 StockBrushes.pressurePen 的压力算法。方案提醒“双重处理”合理，但不是 v24 仍存在的已确认问题。

建议沿用自定义 BrushFamily，明确灵敏度如何影响 r／q、笔锋如何影响有限端部和笔尖。默认关闭速度辅助；缺压用固定等价值。不要把 r、q、短轴比、角度及平滑全部一次改动后凭感觉挑结果，先固定同色同宽样本，再用真实轻压区间校准。

### 5. 铅笔可以优先验证现有依赖，不需先升级

当前版本目录锁定 Ink `1.1.0-alpha09`，最低 Android API31。直接检查本机该版本 AAR，确认已有 `BrushPaint`、`TilingTexture`、`TextureBitmapStore`、`SelfOverlap`；渲染器有接收纹理存储的创建入口。当前应用仍调用无纹理存储的 `CanvasStrokeRenderer.create()`。

因此，**“已有接口”已静态确认，“满足整个铅笔合同”仍未验证**。需要小型验证确认：压力调节局部密度、同笔自交不加深、独立笔迹叠加、固定纹理坐标、API31／较新API与软硬件 Canvas 的一致性。API 名称存在不能替代这些结果。

原方案“部分接口始于 alpha08”的表述需改成以锁定构件为准；当前在线 BrushPaint 页面标注 alpha09，且文档会继续变动。[官方 BrushPaint](https://developer.android.com/reference/androidx/ink/brush/BrushPaint)

若原生路径不满足，再评估局部 Shader／覆盖与密度缓冲。单纯 `BitmapShader + 每笔统一透明度` 不能表示一笔内部的压力浓淡；按事件逐段透明叠画又容易出现搭接深斑。这是候选回退方案必须解决的行为，不是给画笔加一张纹理图便算完成。

材质资源采用共享、按字节限制的缓存；现在每个画布有自己的128条网格缓存，不是全局纹理预算。首期预算仍是待测目标，不能宣称≤512KiB／4MiB已经实现。

### 6. 倾斜扩宽会影响命中、可见范围与编辑

当前粗筛包围盒为中心采样外扩 `width/2`；整笔擦除同样按 `radius + width/2` 检测中心线。套索虽然最终使用实际轮廓，前面仍有这一粗筛。若铅笔倾斜扩宽至4倍，边缘可能被提前排除，出现看得见却擦不到／选不到，或视口边缘被错误剔除。[包围盒](E:/Inkweft/recon/android/core-domain/src/main/kotlin/org/inkweft/core/CanvasViewport.kt:71)、[整笔命中](E:/Inkweft/recon/android/core-domain/src/main/kotlin/org/inkweft/core/InkModels.kt:149)、[套索粗筛](E:/Inkweft/recon/android/app/src/main/java/org/inkweft/app/VisibleInkGeometry.kt:28)

应让配方给出保守最大外扩范围，并在必要时使用真实覆盖做精确命中。选择与橡皮按笔迹覆盖处理，不必把每个微小颗粒孔都变成独立选择区域。

复制、改色、稳线、页面复制和内容导入目前显式重新构造 InkStroke。新增外观字段后这些路径需要统一保留规则。B08中的笔迹旋转／对象缩放目前也不是完整既有操作，应作为模型／变换验收，不要借此顺带承诺新增一套变换 UI。

## 方案还应补充的范围说明

1. **试写与演示分开。** PenStrokePreview 使用正式笔刷，但输入是模拟的；需要标注。轻量试写区使用内存状态，不调用笔记保存、搜索、回收区或 AppDiagnostics 的笔迹记录。关闭时终止绘制与临时作业，不影响共享资源。
2. **导出分两层。** 首批保证现有可编辑副本／整库备份携带配方及资源。笔记 PDF／图片视觉导出单独列后端工作量；可先用离屏测试证明材质不丢失，不能把导出内容副本等同于完成PDF视觉导出。
3. **识别不必照搬石墨噪声。** 当前识别栅格化为黑色路径并扣除遮罩，是规范化识别输入，不是用户可见笔刷预览。可保留这一目的；同时补完全擦净内容不被旧中心线重新识别的检查。
4. **验收必须包含跨页。** 补 B16：同一次手势跨页，共享配方／种子／压力连续性；实时、抬笔及重开不能换材质。B11另补手指先落、笔后落的混合 pointer 用例。
5. **旧格式策略写窄。** 保留现有数据、明确当前旧笔映射；不建设所有历史APK的兼容矩阵，不推测缺失的旧配方。未知新配方或缺失关键资源应显式失败或标识降级，不能当作成功的实线导出。
