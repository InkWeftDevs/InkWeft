# 按改动验证与早期版本策略

## 自动选择

| 改动 | 默认检查 |
| --- | --- |
| Markdown 等项目文档 | Python 选择规则检查、源码快照；不安装 JDK／SDK，不启动模拟器 |
| 核心单测文件 | JVM 核心测试；不启动模拟器 |
| 单个 Android 测试文件 | 构建所需 APK，仅运行该测试类；删除测试或修改测试助手则验证所在模块 |
| 应用界面／资源 | 应用构建、lint、界面集；不重跑数据库集 |
| 核心共享定义、存储、构建脚本、CI 逻辑或无法识别的代码 | 当前版本核心、lint、数据库及界面整合验证 |
| main 上的代码合入、手动 full | 完整当前版本验证 |

PR 后续提交仅在**上一个准确 head 已通过该工作流且仍是祖先**时按本次差异选择。否则回退到整个 PR 差异，避免上轮失败的代码被一次小改动漏过。范围和实际数量写入 Actions 摘要及 android-plan.json。检查计划本身有独立测试。

## 节约时间的具体改动

- 删除固定旧 APK 的检出、构建和历史版本覆盖升级测试；不建立长期历史版本矩阵。
- 设备测试通过 `am instrument` 单次运行，直接拉取这一次的截图和诊断文件。移除「为了抓截图再跑一次全部 UI」的步骤。
- 检查 instrumentation 输出中的完整 OK 与预期数量，不能仅凭 shell 返回码把失败当通过；没有执行的类别在范围记录中明确为空。
- 开启 Gradle build cache；同仓库分支允许写依赖缓存，外部分支只读缓存。缓存不含签名密钥。
- 仅在需要设备测试时安装／启动模拟器；文档修改不触发重型构建。新增提交取消旧的进行中任务。
- 手动 workflow_dispatch 的 full 保留，便于发测试包或调查涉及多个模块的问题。无需每个 UI 文字修改重复整套验证。

首次修改共享纸面定义及 CI 本身仍做一次完整当前版本整合验证，以验证新流程；本地先运行相关用例。后续变更按上表缩小。

## 兼容边界

目前处于早期开发，不承诺历史安装包／备份格式长期兼容。可选择破坏性更新，格式改变时明确告知重建或导出方式，不自动清空用户设备资料。本次纸面扩展保持现有作者表，不新增迁移，不额外承担历史 APK 验证；现有迁移代码不为追求删除而做无关改写。

仍需验证当前版本保存／重开、笔迹身份、取消、备份和导出完整性；允许格式变化不意味着允许当前版本静默丢数据。

参考：[GitHub 缓存规则](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)、[Gradle setup action](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)。实际耗时以每次 Actions 运行记录为准，不承诺固定提速倍数。
