# v48 自动美化与来源覆盖整改

适用：`0.0.48-automatic-beauty`（48）。源码基线为 `8e8adbaf4bb6a9d5e2996fb4a4a615c0528f9238`；本轮改动留在本地工作树，交付回执列出源文件摘要与 APK 身份。作者 schema12／IWO9 不变，覆盖安装保留原资料。

用户确认没有本次“多个字只给出一个候选”的原始区域笔迹，先完成整改与合成验证。因此不能从截图判定原始故障在哪一层首次丢字，也不能把生成的样本称为该故障已复现。真实案例对应 ABF-03，保留待测。

## 已定位并整改

|原实现问题|整改后的行为|
|---|---|
|识别器省略空输出行，字体对象仍可引用全部输入来源|每个输入组保留输出和来源；空行、遗漏、重复或外来来源阻断自动提交，无法生成完整映射的候选不覆盖原迹|
|被拒绝的来源一直进入全页 fresh 集合|按空间单元和不可变原迹指纹记录尝试；输入、补笔或选项变化才重新识别该单元；失败单元保持原迹，不标为已处理|
|两笔中一笔为小点时，高度统计向下取整可能选中小点|采用上四分位向上取整，分行与质量判断使用相同规则；没有降低识别分数门槛|
|段落策略即使质量、来源和布局安全也要求点应用|自动入口在两种策略下都经过完整判断；手动选区继续主动校对、明确应用|
|校对面板默认用候选接管纸面|打开时显示原迹，注明候选未应用；只有用户点击对比才预览，关闭／保留原迹不改自动偏好|
|一个短候选可能隐藏横向很宽的来源|以字体自然跨度和输入高度比较覆盖范围；两种布局都检查。此为保守布局证据，不用笔划数或连通块数猜汉字数|
|解码位置被夹到实际输入边界，丢失越界证据|保留解码的原始归一化位置；实际输入外的候选进入校对，不把右侧填充区域当作作者文字|
|追加片段按新局部高度重新估字号／基线|已确认原位行保持字号和基线；只塑形新片段，无关字形、遮罩和身份保持|
|继承旧字号后的最终合并候选可能越出页边|合并后复用保存层页边界校验，越界直接保留原迹并可校对；无限画布仍使用自身范围合同|
|自动对象写入前乐观展示候选，并阻断下一笔|未确认时显示已确认对象与原迹，允许正常落笔；对象编辑／擦除保持事务边界，确认后才更新已处理来源|

750ms 停笔与250ms第二次等待只用于调度。可靠性仍要求完整来源、两次候选一致、原始分数和竞争字符检查、空间／结构检查、可用布局与无碰撞。两次推理来自同一个随包 ONNX 模型，只说明边距扰动下稳定，不能当成两个独立模型的正确性证明。

## 版本与事务

所有替换来源都完整归属当前片段，未改变的邻近字体片段只被保留，不被借入后整体隐藏。触及已转换片段时，取回该受影响片段的完整原迹并使用现有局部替换；已有擦除／样式冲突继续保留原迹。

原迹仍先进入原保存链路。字体写入沿用 `expectedInk`、对象版本、稳定操作 ID、幂等回执和撤销规则。新输入取消旧推理；写入已发生而回执丢失时，继续显示原迹，核对重试同一操作，不重复写入或吞掉随后保存的新笔。

缓存校对候选更新到新的页面版本前，核对原迹内容及选项；同一个笔划ID的裁切改变也会使旧候选失效。用户主动点击“应用”走手动事务，即使该候选最初来自自动入口。对象容量拒绝会保留原迹、显示校对状态，并在诊断中记为没有进入写入队列，不把它记录成已保存。

单个自动片段超过256笔或布局／分行预算时保留原迹并说明可分段框选。补笔可以改变未完成单元，但静止轨迹无法证明作者一定写完；真实半字长停顿仍需按 ABF-05 记录误替换和介入量。

## 美化诊断

从软件内“诊断与导出”进入：标记时间，点击“开始美化诊断”，关闭面板并在专用测试本复现，返回保存“美化诊断 ZIP”。若要检查现有区域，可主动框选该原迹重新识别，并在反馈中注明这是手动入口。

- 默认仅记录版本、页面／笔划来源映射、点数与笔内时间范围、分组及包围盒、实际张量尺寸和非空范围、候选分数、拒绝原因和提交状态。
- 勾选“另含本次原始区域笔迹、模型输入图像与候选文字”后，另附区域 `.inkweft`、实际归一化 ONNX 输入 PNG、完整解码文字、候选／备选及逐步 top2 分数。只在本机录制并由用户主动保存，不自动上传，不进入基础诊断 ZIP。
- 右侧填充值0、BGR顺序、48像素输入高度、缩放后宽度、额外边距和裁切范围都可检查；PNG反映实际张量，包括填充区。逐步分数不是全词表的完整概率张量，也没有校准为准确率。
- 美化 ZIP 内附 `basic-diagnostics.zip`，用于核对应用／签名和环境快照。原始笔迹的 `elapsedMs` 是笔内时基，不能当成全局真实落笔顺序或笔间停顿时间。
- 仅保留最近3次尝试；元数据与附件分别有上限，达到上限明确记截断。录制留在内存，停止不删除现有笔记，重启会丢失未导出的捕获；强停后的终局回执不在这些内存记录中。基础持久诊断仍只有有限固定事件，不是完整系统日志。

异常反馈优先提供上述 ZIP，只补充日志不能表达的操作步骤、视觉／笔感证据。私人区域附件不加入 Git、PR 或 CI。

## 验证口径

旧实现的四项定向回归均失败，覆盖默认预览、缺来源映射、全页失败累积和段落自动门槛；失败记录保留在本机归档。当前完整结果见 [v48 验证记录](VERIFICATION-V48.md)。

注入候选的测试验证状态、所有权、提交和撤销；实际随包模型测试使用新生成的字体轮廓原迹，分别记录识别错误、正确自动提交覆盖、待校对和错误自动替换，并保存实际输入／输出。字体轮廓属于合成控制样本，不代表真人书写分布，也不是独立评估集。

真人手持笔、用户原始失败区域、多作者准确率、低资源硬件表现、系统保存选择器和最终接收端按 [ABF-01～10](DEVICE-TEST-CHECKLIST.md) 单列待测。输入缺失与输入完整而模型漏字需要不同整改；当前没有真实原迹，识别器对照试验尚未执行。

预处理核对依据为随包 `ocr/inference.yml` 和 [PaddleOCR 预处理源码](https://github.com/PaddlePaddle/PaddleOCR/blob/main/ppocr/data/imaug/rec_img_aug.py)、[CTC 解码源码](https://github.com/PaddlePaddle/PaddleOCR/blob/main/ppocr/postprocess/rec_postprocess.py)。上游能力说明不作为墨织真人识别质量证据。
