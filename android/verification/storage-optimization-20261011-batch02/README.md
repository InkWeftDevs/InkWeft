# 第二轮存储优化：可见复制与按 ID 几何读取

基点仍为 V86 `8596a981a76e27c38caf5220659e0e238141d319`，叠加首轮已验证补丁；未提交。首轮 APK、源码摘要及 14 项设备结果保留在上一批归档，本目录只记录本轮增量。Room16、数据格式、笔迹点字段和容量值均不变，不需要迁移或重建资料。

## 已实现

- 第一批 D：新增 `VisibleInkSnapshot`，在同一事务内冻结页面 revision、可见笔迹及必要掩码。可选指定笔迹 ID；掩码先读引用元数据，再读取实际命中笔迹的掩码载荷。无关隐藏笔迹、已撤销掩码及仅作用于未选中笔迹的掩码几何不解码。必要几何损坏或引用越页仍拒绝。
- 整本复制、单页复制、普通可见内容导出和带作者状态的页面导出采用可见快照；人工索引仍绑定同一源 revision，副本重新映射笔迹、掩码、对象身份。复制各行、引用及 durable receipt 保持原子提交。
- 第一批 C 的复制部分：先在短事务内读取当前引用的原件描述，再在事务外完成 PDF/图片格式校验。提交事务重新读取当前源本的页面、作者状态与原件引用，并按实际插入块重新核验长度和 SHA-256；新出现或未命中内容证明的原件仍走完整格式校验。已经提交的命令先查回执，不重新依赖已变化或回收的源本。
- 第二批 A 的读取子步骤：摘录与新锚点只加载指定可见笔迹和其有效掩码，仍核对固定 revision、作者图层版次、来源范围和引用闭包。内容封面、复习原页及只读来源使用可见快照，原有版次提示保留。冻结/解码计时继续接入现有诊断观察器，观察器异常不影响成功读取。

可见或局部快照表示当前显示/复制所需内容，不是全部保留历史或全库的健康校验。编辑器 `read()` 和全库备份的完整校验继续检查全部保留内容；旧隐藏数据没有删除或重写。
