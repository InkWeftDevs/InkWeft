让大原件按流进入、按页使用

已实现原件逐块读取、512 MB PDF 导入通道、PDF／图片全库字节门槛移除、8 GiB 本地全库备份和安全离屏页面释放。64 MiB Java 堆完整处理 300 MB 合成 PDF 与超过 1 GiB 的备份流；安卓原生和真实课件验收仍待本地。

这次扩容先改变读取和存储路径：数据库仍保存权威原件；每次只取一个 512,000 字节块，用 64 KiB 缓冲增量校验。需要随机访问的原生引擎使用完整校验后发布的文件，连续页复用同一文档句柄。导入流写入暂存文件时同步计算摘要，取消或失败只清理未完成文件。

本轮落实

  • PDF 和图片读取返回长度、SHA-256 和可重复打开的流；渲染、EXIF、区域解码与文字搜索改用文件。完整复制检查长度、尾部和摘要，存储块在原有作者事务内写入，receipt 保持幂等。
  • PDF 文件缓存复用 SHA 身份；1 GiB 缓存预算只约束可重建副本，租约保护正在使用的文件。重启后首次使用会校验缓存，损坏则重建；空间不足或取消不会发布半成品。设置新增原件占用、设备剩余空间与缓存清理。
  • 移除 PDF 全库 80,000,000 字节、图片全库 32,000,000 字节的写入和备份恢复判断。整本复制直接按页复制原件，不再先编码成受 96 MB 上限约束的交换文件。当前数据结构中的单原件长度仍为 Int；512 MB 范围内统计与空间预算用 Long 运算。
  • 本地备份 v2 上限 8 GiB，旧 v1 的 1 GiB 流仍可读；保持摘要、外键、语义验证、隔离暂存和恢复原子性。验证逐件使用原件流，不再在 documentCache 中保留整库 PDF 数组；取消时收回未交付的快照和暂存库。
  • 连续阅读正文只观察可见页、相邻一页及选中页。批注在 IO 解码，全本只观察每页最多 8 KiB 的图层权限头，保留远处跨页写入的原权限和版本。
  • 未被显示且保存已确认的普通笔迹页可释放几何；撤销逆操作只保留 ID，重载后核对 revision。版本改变时不重放旧逆操作。队列、草稿、检查点、跨页联动撤销、美化校对、对象编辑历史和另一显示位置仍在使用的页继续保留。取消／过期 PDF 帧释放尚未接收的位图。

StarNote：新的 PDF 原生证据

针对静态 APK 5703 的 libengine_sdk.so，按 ELF 符号体长分别恢复了 nativeOpenDocument、nativeOpenDocumentStream、neopdf_openDocument 和 neopdf_renderPage，四个入口均完成有界伪代码恢复。没有执行 APK／原生目标或复制第三方实现到墨织。

证据可以确认范围
JNI 取得 UTF 字符串，经 ELF PLT 重定位调用 neopdf_openDocument原生 SDK 提供按字符串路径打开文档的入口SDK 静态能力；JNI 类型与内部类型仍需结合运行时核对
流对象 read 的签名 (J[B)J，同时查询 name 和 length()JSDK 支持以偏移和字节缓冲进行位置读取，以及 64 位长度只读取少量接口元数据；实际应用选择该接口尚未采集
renderPage 独立传入文档句柄、位图尺寸、页参数与绘制范围；ELF 包含 pdfium / CPDF_Document 类型字符串原生页绘制与文档读取可分开；存在 PDFium 相关引擎证据未确定 PDFium 具体发行版、缓存限额或 StarNote 5704 页面实际路由

之前的 5704 采集支持 Java 按页取数据／保存的观察，967 个调用配对；它没有覆盖大 PDF 导入或实际 Blob 读取。用户报告 StarNote 能导入 300 MB PDF，因此墨织按该规模推进；不能据此认定 StarNote 不限容量，或认定原件必定存为 C4Blob。标准用户的最大笔记本数量仍是计数配额，未当成字节配额。

见 原生证据和身份。后续只需本地补采导入与翻页时路径／位置读取／Blob 的调用关联；现有证据足以指导墨织的流式文件方案。
