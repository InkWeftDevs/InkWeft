这是 repository 层探针：初始目录通过 Flow.first() 读取，保存期间不持续收集 UI 目录流，也不测完整 UI 渲染。保存负载是扫描开始后由一个协程连续提交 30 次，每次等提交完成才发下一次，并非固定速率到达。基线首个写入等待 Room 搜索事务结束，余下保存主要发生在搜索之后；候选允许读写真正重叠，CPU/I/O 竞争及 WAL 快照影响可能随之不同，尚无分段计时。这解释了为什么最大延迟显著下降而 p50/p95 可能上升，但不能据此定量归因。p50 使用排序后的第 16 个值，p95 是第 29 个，max 是第 30 个；未导出逐次向量。第二次完整搜索配对同样通过，结果单独保留，不混合中位数。方法审计见 `search-measurement-audit.json`，原始四轮摘要见 `repeated-search-summary.json`。

## 改动与不变量

- 搜索使用独立、可取消的 Requery deferred 只读 WAL 快照。待建原文在 SQLite 回调中使用原有 Kotlin Unicode 子串规则核对；只将命中身份放入临时表，保留已索引与待建来源的完整性、旧识别版次过滤和页面优先导航。
- 资料库目录观察不再读取正文。分类与稳定排序在 SQL 中完成，先物化 `LIMIT/OFFSET` 的一页身份，再按主键读取短预览；打开、恢复和重命名按需读取完整正文。来源跳转等待真实打开成功后才确认。目录元数据仍随刷新读取，非空查询仍核对候选笔记正文，不声称整次查询只访问 60 行。
- 瓦片正文读取按实际脏区筛选，保留绘制顺序；同源、同版本的有界几何缓存减少小数平移和缩放时重复解码。完整瓦片复用仍要求相同采样网格，缩放预览不算完成帧。每次缓存访问核对版本、空间身份和擦除 epoch；精确输出与冷重建对照。
- GC 引用与占用扫描一次，将候选身份保留在私有临时表，每批仍通过 Room 短事务删除至多 256 条。主写连接的 `data_version` 和 `total_changes + pending invalidation count` 区分本次删除、Room 通知重置与其他写入；任何作者写入保守推迟后续批次。守卫依赖锁定的 Room 2.8.5 行为，缺失时停止删除。历史根、最新来源、回执和损坏保护保持。

没有持久 Room schema 改动。临时表、FTS、解码缓存都是派生数据，不进入作者备份。

## 公共建库修复的边界

稳定的旁路文件锁覆盖当前版本 helper 的首次初始化与 schema 回调，成功打开后恢复原 helper 快路径；不删除锁文件，避免等待进程锁住旧 inode。既有非空数据库或任何恢复侧车都交给 SQLite 原路径，保留作者数据。五项新增/扩展原生测试验证普通新建、既有 1024 字节页库、损坏保留、两个独立 helper 并发、空文件及 schema 回调中断续建；两个 helper 在同一进程运行，不是跨进程实测。

绕过旁路锁的旧版或外部创建者若在空文件预检之后抢先完成建库，平台打开及 PRAGMA 可能先改变其 journal/auto-vacuum 参数，再被 schema/version 检查拒绝。当前没有发现作者行删除路径，但此竞态未经原生跨进程验证，不能保证其文件字节或参数不变，也不保证两个版本同时初始化成功。所有现有生产建库入口均使用该工厂；本次两 helper 原生测试验证的是遵循同一锁的并发场景。无有效页头但残留侧车的特殊中断仍优先保留侧车并交给 Requery 恢复，可能采用原默认 1024 字节页，不声称所有首次创建中断都恢复为 4096。关闭后删除或替换数据库仍要求上层先停止在途访问。
