# Warm causal diagnostic static review

The unused empty-draft CTE branch is reverted; existing paging correctness tests are retained. This is a simplification after mixed focused results, not a measured speed improvement. The default warm page SQL reconstructed for query `target-only`, no drafts, `byTitle=false`, pageSize 60/offset 0 is byte-identical to d66b60d (SHA in the adjacent JSON).

Only `LibrarySearchRepository.kt` and new `LibrarySearchCausalTest.kt` were edited by this task. Repository also wires the parent-owned `onBatchStep` through a default-null observer. Public paired probes, prior evidence, gates and sampling are unchanged. No Gradle, Android device, CI or GitHub action was run by this agent.

Default UDF observer null registers the existing native callbacks, performs no new clock reads and creates no statistics objects. Enabled mode registers title/body/tags functions with the same argument count/default flags and preserves cancellation, nullable text handling and Kotlin `contains(ignoreCase=true)`. Source checking retains the prior scan observer ordering. Statistics aggregate callback count, UTF-16 length and matches, plus synchronous conversion/contains thread CPU and wall intervals. Failed/unsupported/negative CPU timing is explicitly invalid. Page timing covers query/cursor work on one native caller thread. Observer exceptions cannot replace an earlier cancellation or read exception; they are suppressed on that primary failure.

The large opt-in method is `org.inkweft.data.LibrarySearchCausalTest#warmUdfCostsAndQueryPlanAgainstInMemoryReference`, with `-e libraryCausalDiagnostics true`. It constructs the exact logical public warm fixture (500 bodies of 20,020 UTF-16 units, 20,000 indexed page sources, one author after 61 committed saves). Runtime file/page placement and preceding cold/concurrent workload are deliberately not reproduced. UDF-off production reads before/after collect their actual SQL and EXPLAIN; one additional instrumented plan read checks statement equivalence after renaming functions and plan equality. Three separate profiled reads omit EXPLAIN. Later, full saved heads/tags are loaded and three synchronous Kotlin OR-match references use the known synthetic page/card hit sets. Loading is reported separately and is not included in reference matching. The reference omits FTS, SQL, sorting and full result assembly and is not a library read benchmark.

`profiledContainsPreservesUnicodeAndSourceResults` runs without opt-in: 8 queries × pending/indexed paths, five synthetic field/source placements, exact profiled/plain result comparison plus independent Kotlin expected membership. It emits one bounded correctness summary. The large method emits one bounded causal summary. The marker schemas restrict SQL to exact expected strings and plans to SQLite operators with known identifiers; neither emits author text or IDs. Both are bounded at 32 KiB UTF-8.

Interpretation limits: callback clocks and additional registered UDFs perturb enabled timings. Conversion captures `Args.getString` inside the callback, not SQLite's earlier evaluation/materialization nor all JNI work. Remaining page time cannot be assigned wholly to JNI, I/O or locks. Callback totals do not count underlying storage pages. A different query plan or repeated UDF invocation is evidence to inspect; performance thresholds are never inferred from these diagnostics. Build and native validation remain the parent's next step; this document establishes static review only.
