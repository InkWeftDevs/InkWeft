## Marker contract

Marker: `RASTER_CAUSAL_DIAGNOSTIC`, exactly three successful records with result.layers `[1,4,8]` in order. Each original UTF-8 JSON payload must be at most 262144 bytes (enforced in the test). Schema is the closed JSON Schema subset in `raster-marker-schema.json`. There are exactly 5,20,40 frame records respectively (65 total), at most 128 metadata and 128 read records per marker. Each frame has at most 18 stage timestamps and 18 corresponding thread IDs. Only finite synthetic counts/timings, numeric layer indices, fixture logical digest, fixed labels/settings and bounded resource fields are output; no stroke/page IDs, note content or pixels are logged.

Additional semantic checks beyond schema:

- `fixture.seed == seed == 4101`, fixture.label is `raster-{result.layers}-before`; `frames.size == 5 * layers`, numeric layers lie in `[0,layers)`.
- Each layer has active phases `first/local/hidden-local` and full phases `full/hidden-full` exactly once. Their revisions are 1/2/3/2/3 respectively. Generation is increasing within each raster role/layer, but full clear increments generation and must not be assumed contiguous.
- `timesNanos` and `threadIds` key sets match. Successful frames have the required 11 core stages and no FAILED/BUDGET_BUSY/SUPERSEDED. A CANCELLED stamp can follow successful publication when clear races the coroutine's final unwind; actual join and pixel checks are the authority, so do not infer an incomplete frame solely from that optional stamp.
- Core order: REQUEST <= WORKER_START <= METADATA_START <= RASTER_START <= PREPARE_START <= PREPARE_END <= PUBLICATION_ENTER <= PUBLISHED <= READY_DRAW_START <= READY_DRAW_END. WORKER_FINALLY follows PUBLISHED but may precede or follow READY_DRAW. Notification enqueue/callback order can be checked only when both exist. Do not require callback before READY_DRAW.
- `nativeAttempts == nativeCompleted` on successful frames; sums of active/local nativeCompleted equal result.nativeStrokeBuilds. Native is still per-frame construction, not cross-frame native caching. Counters measure the existing work and are not required to improve in this diagnostic.
- Successful metadata has one record per frame (5 * layers); each phase/layer occurs once. `preparationRows` is existing work-row sum, not unique-stroke count. Read records are tagged by phase only, not frame/layer; do not invent a per-layer read identity or a read record for a cache hit.
- `localDecoded < fullDecoded == 321`, `0 < localRebuiltTiles < fullRebuiltTiles`, pixelsEqual and joined true. Retained resource totals/inFlightJobs should be checked against controller expectations; the test itself checks actual Job completion and return to its initial worker/geometry baseline. Resource numbers are tracked estimates, not proof native/GPU heap equals zero.
- Metadata CPU requires corresponding endpoint thread IDs equal and must remain null if unavailable. Thread CPU is not host cycles. No new acceptance threshold, quantile distribution, pooling with old diagnostics, or replacement of original common performance samples.
