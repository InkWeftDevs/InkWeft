## 修复范围

| 问题 | 实现与可验证行为 |
|---|---|
| A01 大页读取成本 | 事务触发器维护每页笔迹总量和各层/类型计数。编辑器只读所需身份及小型统计行；读取观察增加实际载荷字节、解码点数和返回候选数。空间查询验证真实执行计划，并对固定视口逐级增加无关笔迹。返回候选数不等于SQLite内部VM步数或访问页数。 |
| A02 首次索引事务 | 空间索引每批最多128条、2MB已处理载荷；擦除目标索引每批最多128个遮罩，并在达到4096个成员后让出写入，单个遮罩仍按既有最多20,000目标的原子单元处理。每批提交后取消可保留进度；结果只在当前页待补建队列清空的事务中读取。显式整组作者操作保留原有事务一致性。 |
| A03 多层读取与位图 | 先查可见范围元数据、再在SQL筛选图层后解码；页外/隐藏层不分配整视口缓存。一个画布共享8,000,000像素（约32MB RGBA）保存笔迹预算，各层裁切到实际范围，密集叠层同比降低缓存分辨率；仍保留完整内容与独立层语义。 |
| A04 旧帧隔离 | 页面、版次、图层、选择排除、允许集合、视口及绘制参数进入帧身份。只允许有相同纯追加代次证据的旧帧暂时复用；变换、删除和选择排除立即停止使用旧像素。 |
| A05 密集区域操作 | 选择/擦除按操作范围分批读取；图层可见/可写条件在SQL中过滤，类型过滤先于结果预算。变换选择最多1024笔/131072采样与遮罩点，擦除最多20,000目标并只保留ID。版次或权限变化、取消、超预算不发布部分结果。图片摘录独立于变换选择预算，可选OCR最多256笔/65536点，超限保留图片。 |
| A06 备份阻塞与预检 | 独立只读连接从已提交WAL取得一致数据库副本；在隔离库校验和流式归档，原件维护锁只阻止GC/迁移。按真实归档格式预估字节，重复原件引用按实际输出次数计数；副本前及捕获后复核容量和磁盘空间。 |
| A07 上传事件循环 | 分块请求把连接、SQLite写锁等待、摘要及BLOB操作作为完整单元交给最多4个工作线程。取消响应后仍可通过清单/回执确认已提交块，幂等重试后继续发布。 |
| A08 资料库搜索 | IO中的可取消单次文本遍历、筛选和排序替代Composition里的逐本重复扫描；150ms合并连续输入，清空/分类立即更新。结果只携带轻量命中与导航目标；查询代次和查询/筛选参数共同约束显示及点击。 |
| A09 相关状态边界 | 跨页混合操作先冻结并验证所有参与模型的作用域，再进入待提交；失败不遗留第一页面的半组排队操作。没有为单纯架构风格进行整页重写。 |

云备份仍为500MiB协议上限，本地完整备份仍为8GiB；没有把服务端协议扩容或所有硬件性能提升列为已完成能力。延续V87格式要求，不新增作者数据/备份格式迁移；旧包降级仍需在独立环境用升级前备份重建。

空间索引增加页面桶这一维，桶使用UUID稳定哈希的低24位，能被RTree的float32精确表示；碰撞只增加候选，完整页面UUID仍必须匹配。查询固定从带页面和XY范围约束的RTree开始，再按身份读取作者行，避免扫描整页，也避免把其他页相同纸面坐标全部当作空间候选。旧二维或缺失索引只重排派生补建队列，不修改作者行；首次读取仍分批提交。[SQLite的RTree维度与相交查询规则](https://www.sqlite.org/rtree.html)是这一实现的依据。

主机SQLite3.49.1的可复现SQL诊断中，固定命中8笔，另加10,000条其他页同坐标笔迹：

| 当前页可见笔数 | 原查询VM步数 | 修复后VM步数 | 返回笔数 |
|---|---:|---:|---:|
| 1,000 | 30,163 | 371 | 8 |
| 10,000 | 300,144 | 340 | 8 |
| 100,000 | 3,000,144 | 343 | 8 |

脚本和结果在归档的 `verification/explain-view-query.py/.json`。该计步不包含RTree内部C实现的节点遍历，也不能换算为Android帧率；设备回归另验证实际查询计划、载荷和解码点数。

MuMu5/API32实际查询计划以带6个范围约束的RTree为起点，再按ID取作者行。在同一固定视口、全部笔迹均可见但无关笔迹离屏的1,000／10,000／100,000笔场景中，每次均返回8笔、解码16点、读取832字节；预热后冻结读取分别为2.609／2.048／2.170ms，解码分别为0.373／0.262／0.158ms。这是单次合成观察，不是硬件性能分位数。

这些检查证明没有按层重复解码、预算内仍显示可见笔迹及隐藏层像素缺席；8层软件合成仍较慢，不能据此声称达到60fps。原始 `readyMs` 字段还包含后续30次计时绘制，不用作首帧耗时。逐条JSON在 `app-first-runner.txt`，同次运行的另一个原子性用例因测试对象身份比较失败，与此像素/预算用例分别记录。
