## 实现

- 保存笔迹按最多512×512采样像素瓦片保留，裁切边缘对齐相同采样网格。投影和分辨率相同的瓦片由空间条目身份、候选顺序、排除集合和擦除代次验证；局部追加/隐藏只重建变化瓦片。脏区按范围批读，完整新帧完成后一次发布。图层配置、擦除或投影改变采用保守失效。铅笔内部的 PencilTileRenderer 继续使用。
- 每个画布继续共享8,000,000采样像素预算，全局 RenderResources 继续受128MiB逻辑预算约束。缓存倍率取不超过预算的二次幂，密集层可比V88使用更低的缓存分辨率；不同倍率不复用瓦片。活动/工作引用同时计账，取消后释放，不把弱引用或未完成帧当可交付画面。
- 新存储笔迹含36字节保守范围头，读端仍校验真实几何与头一致。空间补建先通过小型前缀建立覆盖，未知范围用独立可恢复队列逐批处理，避免反复扫描已覆盖的离屏条目。当前区域只补建相交几何，可留下离屏 pending；整页范围、复制、导出等仍完成所需全量读取。没有范围头的旧笔迹完整解码回退。每个读取事务重新检查覆盖；作者变更触发失效，版次改变不发布结果。
- 页面识别/人工文字及卡片正文使用原生 FTS4 的派生索引。Unicode大小写折叠及1/2/3字符候选保留中文短词、标点、补充平面字符；查询只传生成的ASCII token，候选再以现有 contains(ignoreCase=true) 核对原文。来源触发器维护持久待建队列，每批最多64行、约1MB源文本后让出作者写入。首次搜索须补齐该派生索引，取消保留进度；清空搜索直接读分类，不等待索引。
- 资料库按已有置顶/标题/最近顺序扫描轻量书目，每页最多60本；最多多确认一条命中作为下一页游标。页面和卡片原文只读取当前候选，新筛选/排序/草稿从第一页开始；旧识别版次、回收页/卡片继续排除，页面命中导航优先。笔记正文及草稿仍来自已有书目状态，未在本轮重写整套书目加载合同。

FTS使用现有SQLite依赖，不引入网络服务；[SQLite FTS4文档](https://www.sqlite.org/fts3.html)描述原生MATCH和派生表机制。原生词语分词不等价于原先的Unicode子串搜索，因此本轮生成候选并保留原文核对。

## 格式与边界

Room/作者备份schema不变；范围提示、未知队列、擦除代次和FTS表均为可重建派生材料，纳入备份/Shadow的schema覆盖检查，不作为作者行导出。V89可读取已有笔迹；V88及更早程序不能读取含新范围头的数据库/检查点/备份行。升级前保留备份；降级在独立环境从升级前备份重建，不直接打开升级后的库，也不删除用户资料。

首次覆盖仍需读取本页所有未知范围的小型前缀；旧格式首次索引及擦除关系补建仍可能耗时。瓦片验签仍读取可见候选元数据，脏区不连续时其并集可能多解码一些未变笔迹；平移/缩放及缓存倍率变化仍完整重建。本轮没有声称恒定首帧时间、任意密集页无停顿或真机60fps。FTS是额外派生磁盘开销，常见短词仍可能命中大量候选。
