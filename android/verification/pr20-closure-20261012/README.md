## 本轮生产变化

- 删除 `PreservingOpenHelperFactory` 中全部平台预初始化及页大小、auto-vacuum 设置。普通创建和恢复交给 Requery；旁路文件锁仍覆盖当前版本首次打开及 schema 回调。本环境新建库实测为 1024 字节页 / FULL，既有库不由工厂强制重排格式。不能据此承诺 SQLite 普通打开绝不更改任何元数据。
- GC 将临时根身份的逐条插入合并为每批最多 128 个身份 / 256 个绑定参数；严格解码、取消检查、尾批写入及后续活引用保护保留。原有一次扫描、短删除事务与并发写入后保守推迟规则不变。
- 备份仅对私有快照和私有导入阶段的验证使用事务，复用私有事务上下文，旨在减少 DAO 调度开销。共享的 `validate()` 不统一加事务，避免影响调用它的活库路径。
- 一笔笔迹命中多个脏瓦片时，在该笔的瓦片循环内惰性构造一次不可变原生 `Stroke`。没有跨帧原生对象缓存；笔刷、裁剪、图层、顺序和变换保持。
- 索引改为在普通读查询后、作者写事务外预计算词项；提交事务内核对 pending 仍存在且可空的标题/正文完全一致，然后重新取得当前 doc key、原子更新 FTS 并清理 pending。过期项保持 pending，整批过期仍继续重试。64 条 / 1,000,000 原文 UTF-16 字节预算、首条超额仍推进、10 ms 批间让步及 Unicode 规则保留。原文预算不是堆内存上限；保留一批生成词项会增加峰值堆，并发 builder 可能重复预计算，尚无峰值堆实测。FTS 写入与原文核对仍占用作者 writer，不能预先承诺消除全部等待。已有独立搜索快照、待建原文过滤和摘要分页继续保留。

## 新格式配对方法

这里的 FULL 指 `auto_vacuum=1`；实际 writer 同时记录 `page_size=1024`、`journal_mode=wal`、`synchronous=2`。性能基线为固定 `a128bb07` 加与候选逐字节一致的安全工厂及三份性能探针，只有这四个路径变化。不能称为完全未修改的原始基线。`baseline-final-provenance.json` 和 `baseline-final-source-manifest.json` 是最终探针对照；更早 baseline-v3/closure 文件仅保留历史阶段。

两端同一模拟器，三份共同探针源码逐字节相同，采用同一规模与内容规则、新建合成库，UUID 和部分时间戳不同，不能称为字节相同数据库。另跑的 `TileLocalRedrawTest` 在候选 pan/zoom 用例增加了 decoded=0、reusedStrokes>0 两项缓存断言；local append 的方法、夹具及计时路径相同，不能称整份 Tile 测试源码逐字节相同。实际 writer 的 page_size、auto_vacuum、journal_mode 和 synchronous 在计时结束后、Room 主写事务内只读采样；不靠配置推断格式。

Library 探针保留直接冷读期间连续 30 次保存，另加真实 `observe()` 自动索引期间连续 30 次保存。后者记录每次保存开始/结束的已提交索引行数及原文扫描数，只有计数实际推进的窗口支持重叠结论。`searchIndexReadyMs` 在保存结束且已观察到正确 pending=0 结果后取值，是联合完成时间，不是首次就绪回调时间；`firstCommittedBatchMs` 和 `allIndexRowsCommittedMs` 在对应回调取时。它不是完整 Compose UI 性能测试。

GC 探针未逐次断言 rename 返回 `Committed`，其分位数是调用完成时延；并发提交正确性另由独立原生回归验证。`liveFirstPassDeferred` 只表示首次收集返回 deferred，探针未记录该次删除数量，不能推断先零删除后暂停。暂停扫描的另一场景明确断言零删除。

保存向量保留原顺序。Library p50 为排序第 16 项，GC p50 为第 15 项；两者 p95 均为第 29 项、max 为第 30 项。GC `liveCollectionAndSavesMs` 包含 30 次保存和补充清理，不能称纯 GC 时间。数据层字符数是跨 cursor 返回的 UTF-16 单位，不是磁盘 I/O 字节。分母为零或旧版缺少计数器时不补零、不计算变化率。

此前 4096 / INCREMENTAL 配对属于旧初始化路径，继续保留，但不能代替本轮 1024 / FULL 配对或与其混合。
