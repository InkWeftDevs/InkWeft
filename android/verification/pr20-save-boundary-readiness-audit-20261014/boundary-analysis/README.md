The parser requires exactly the fixed IDLE, DIRECT, OBSERVE order, seed 4101, 30 committed saves each, initial revisions 1/1/32, matching fixture hashes and all six table counts, writer PRAGMAs, contiguous 96-event chunks, declared exact event counts, no overflow or invalid flag, and one exit for every recorded writer submission. Every arm must be a contiguous RESULT → EVENTS → READS → END block; unknown/additional/missing fields are rejected throughout its finite schema. The 24 boundary and 50 read-stage enums match the controller contract, implemented independently. IDLE has no read events; DIRECT requires its unique ordered control start/end, and OBSERVE requires a committed-index readiness witness. Marker payloads are capped at 32 KiB (END 4 KiB), 7 MiB total. The contract preserves the original PUBLIC direct → paused-reader save → observe sequence. IDLE is an independent fresh-database control; mode differences are not additive costs and a candidate-only trace cannot establish B→C1 causality.

For each sample, task ordinals must agree at all author boundaries. All 22 required author stages must exist uniquely; Room and selected SQLite BEGIN/success/END each require both entry and exit. All body points, including head/read/write/revision/receipt, must belong to the worker and occur in their actual sequence. The parser selects the depth-one SQLite transaction that actually spans author body entry, rather than a Room trigger-sync transaction or nested DAO END. Transaction ordinals, depths, success-request flags and outcomes are checked. The twelve disjoint wall segments cover request through caller return. All original save fields, events, read/index events, marker objects and order are retained. Per-thread wall and CPU stamps must be nondecreasing in that thread's original queue order, checked separately for the boundary and read queues. Different threads may stamp and enqueue in a different interleaving; no global timestamp order is required and raw events are never sorted to manufacture a causal order. The small pre-request/post-return portions of the test timer are separate. Executor run-exit may follow caller return and is never subtracted as a save segment endpoint.

Same-thread endpoint CPU differences are available; cross-thread CPU is null. Same-thread CPU still includes intervening work in a suspended event loop. SQLite END covers synchronous commit/rollback **and connection release**, not pure fsync or lock wait. Room post-END includes invalidation scheduling; the final return tail includes coroutine context and scheduling. Public acceptance thresholds are neither implemented nor changed here. Component quantiles use nearest rank within each original 30-save arm; do not sum component medians or pool arms.

`COMPLETE_DIAGNOSTIC_TRACE_ONLY` only means this marker contract and association passed. Original JUnit/host status, process exit, cleanup and source/environment binding need the independent run audit. No production optimization is selected by this parser.
