# V91 Go 云备份与第 2–4 项性能优化

版本 `91 / 0.0.91-cloud-performance`，Room19。工作分支 `codex/storage-optimization-20261011`；基点 `b7594ac953338b56ca4e73050c43bb83137c23f5`。逐项实际结果见 [results.json](results.json)，本机原始证据、容量归档和安装包保存在 `E:/Inkweft/archives/2026-10-12/InkWeft-Cloud-Go-Performance/`。不同轮次的构件身份随回执保留。

## Go 与 v2

生产服务为 Go 程序，Python 保留为旧协议、TLS 和故障验收夹具。单份明文 8 GiB，账户/全站默认预留 32/128 GiB，可配置；SQLite schema 2003 管理身份、配额、租约和永久操作回执，密文以不可变 1 MiB 文件持久化。文件及目录耐久后才登记接收回执；发布用 64 KiB 缓冲分段校验，约每 2 秒持久化进度，最终短事务改为已发布。

Android 使用 IWBK2。创建副本前核对服务器身份、v2 能力和容量；上传 seek 缺块，55 秒执行片后保留原任务；下载 fsync 后登记位图，复核已登记块再恢复。完整 SHA/GCM 和作者引用校验通过后才提供恢复确认。内存预算暂时不足保留自动续传，确定损坏的本地密文停止自动重试。

旧 Python schema 1，以及此前实验 Go schema 2002，不自动迁移。保留原目录、客户端和恢复密钥，使用新私有目录运行当前 Go，再从已确认的作者资料生成 v2 备份。旧 v1 待办在原服务完成或显式放弃后重建；不自动删除用户资料。构建、配额和完整服务备份步骤见 [GO-DEPLOYMENT.md](../../../backup-server/protocol-v2/GO-DEPLOYMENT.md)。

## 实际容量验证

三种输入均由原生 `LibraryBackupRepository.snapshot` 导出完整作者归档，包含实际 PDF 原件与引用。大容量应用探针把该归档经原生加密生成测试队列，再使用生产 `BackupEngine` 上传、下载、校验和空库恢复；它不是三个容量的备份按钮 UI 验收。恢复逐个读取独立原件并核对 SHA-256。

600 MiB 上传约 49.4 秒、恢复约 83.9 秒。2 GiB 上传约 157.8 秒，客户端读取量精确等于密文 2,147,647,794 字节，发布后续校验片读取量为零；恢复约 362.8 秒。2 GiB 下载在写块后、位图提交前、位图提交后三处实际终止应用进程，重开后恢复完整；这些故意退出的 JUnit 记录保持失败/未完成，独立切点回执验证通过，不充当普通 JUnit 成功。

最初缺失清单规范化末尾括号导致服务端 409，已修复并加入独立固定向量；以前的零进度结果作废并保留。8 GiB 主机到模拟器输入复制曾超时，续传前先核对已复制前缀摘要，最终核对全文件摘要；输入复制不算云传输通过。所有故障和修正后的结果分别记录。

## 第 2 项：多层画布

每层一次批量元数据查询建立所有瓦片候选签名；平台帧通知合并。相同投影和采样网格的整像素平移复用内部瓦片，缩放先显示同源变换预览再生成完整帧；预览不能确认捕获完成。预算、版次、图层顺序与擦除关系继续参加失效判断。

3000×2000 软件画布、320 笔场景，基线及优化各 5 轮，局部追加完成时间中位数如下。全部最终像素与冷重建相同。

| 可见层 | 基线 ms | 优化 ms |
|---|---:|---:|
| 1 | 82.811 | 54.544 |
| 4 | 158.374 | 119.100 |
| 8 | 298.955 | 191.316 |

8 层优化后的 5 轮局部完成均小于对应冷重建；4 层有一轮局部 135.875 ms、冷重建 135.736 ms，不删除不利样本。混合笔刷平移复用 8/20 内部瓦片，只重建 12 块；平移和缩放最终像素均相同。时间包含测试等待与软件合成，不表示 GPU 帧率、笔尖延迟或物理平板性能。

## 第 3 项：首次搜索

后台每批最多 64 行/约 1 MiB 原文建立派生 FTS。查询同时覆盖已索引候选和待建原文，首次查询不再等待整库索引完成；候选仍以 Unicode 子串规则核对，过滤回收及过期识别版次。FTS 驱动候选查询，避免为每本重复扫描全部 FTS 行。

500 本/20,000 页首次完整命中约 3,663 ms，暖查询中位数 8.860 ms；存储整合复验对应 3,275 ms/6.946 ms。第一次尚有 20,000 行待建仍返回完整结果。此前暖查询约 2,913 ms 的失败性能记录保留。首次待建原文扫描仍有成本，不承诺零等待或固定 SLA。

## 第 4 项：历史审计与安全整理

审计通过独立只读 WAL 快照和可取消原生查询扫描引用，不占 Room 作者写事务。整理每批最多 256 个可回收身份，提交前在短写事务核对 `data_version`；期间任何提交均推迟本批删除。历史笔迹、版次、回执及引用来源全部保留，不按年龄或隐藏状态删历史。

20,000 来源版次/历史卡片根的暂停探针中，基线 500 ms 内不能完成作者编辑，优化后可以。非暂停审计与 30 次编辑合计 663.012→346.386 ms，编辑中位数 7.604→4.374 ms、P95 10.130→6.223 ms。取消及随后保留核对合计 162.229→108.266 ms，不能称为纯取消响应时长。所有历史根保持。
