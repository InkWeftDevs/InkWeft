# A3.3 已保存资料库备份与无覆盖恢复

这是继续集成的检查点；用户的实机测试继续延后。代码存在不等于用例通过，以本轮CI的原始XML与截图为准。不自动合并main，不发布Release，不要求卸载/清空旧资料。

## 格式与隐私

`.iwbackup` / IWLB version1 是已提交作者资料的固定类型记录流：覆盖Schema6的全部12张作者表，包含原始笔迹字节、隐藏笔迹、局部擦除记录、笔记与页面身份、回收站、封面分类、阅读位置、人工索引（包括已失效项）、已有修订与回执。不是复制一个运行中的.db文件，不携带SQL、DDL、压缩包路径或可执行代码。新增表或列会阻断备份，而不是悄悄遗漏。

仅备份已经保存的内容。不含未保存正文、正在书写未抬笔的一笔、内存撤销栈、设备笔盒配置、缓存/诊断和密钥；不能生成当前产品尚不存在的跨进程撤销能力。当前作者数据均在数据库，PDF/外部附件尚未接入，未来必须扩展格式及完整性合同。

文件是明文，包含回收站及隐藏内容。创建前须明确勾选范围确认；SHA256仅校验损坏，不是来源认证或加密。文件提供方可能是云盘，用户主动选择位置；应用没有新增联网权限、账号或云服务。写入完成不代表提供方已完成远端上传。

## 一致性与恢复

- 在Room事务内校验并导出一致快照，流式读取行和写入文件，不整库读入ByteArray；本轮会占用一个事务，尚不宣称大库不影响写入延迟。
- 恢复先进入应用私有隔离数据库，用本地固定Schema建表、绑定参数插入数据。总摘要、列型、行数、UTF8、有限数值、引用、历史归属、笔迹格式、SQLite integrity_check/foreign_key_check通过前不改现有库。
- 显示笔记/页数/回收站数量，用户确认后，在同一事务内加入所有不冲突记录，读回规范化摘要一致才提交。
- 空库可完整恢复。现有不相交的笔记保持不变；同一集合已完全恢复且未改变时返回ALREADY_PRESENT，不生成副本。任何已有同身份不同内容或历史命令ID冲突都阻断整批，不自动覆盖、不部分混合旧新修订。
- 用户恢复后的新修改受到保护；本版不做覆盖现有库、自动冲突合并、回滚到旧快照或修复已损坏的原数据库。不要为完成恢复而删除用户资料。
- 事务前失败回滚全部写入；提交后回应丢失可对原备份核对重试。若之后编辑造成差异，则拒绝覆盖，不武断宣称原恢复未发生。

## 预算和临时资料

初始保护上限：128MiB记录流、500000条记录、单字段2000000bytes、500本/20000页；每本/每页原有笔迹预算继续生效。源提供方的名称、扩展名、available或size不作为安全判据。保留至少32MiB可用空间，隔离写入过程重复探测。上限不等于已验证所有最大规模的性能。

快照和隔离库位于应用私有cache/library-backup。正常完成、取消、异常和ViewModel释放会清理所持有资源。强杀时临时残留的租约式清理/跨进程恢复尚待完善，不把该目录当作可靠备份位置；真正备份由用户另存。作业仅前台使用，不声称后台续跑。

## 入口与检验

资料库底部提供单一功能入口，编辑页不加常驻说明条。区分备份与诊断/内容副本。新增14项纯核心、12项真实Room、3项UI测试：损坏/截断/未知Schema/大字段、原身份和历史保留、重复恢复、不相交库保留、冲突拒绝、提交前后故障、重开、明文确认和隔离预览后恢复。第三方最终文件选择器/云端上传不由测试自有URI替代验收。

数据库版本仍为6，无新迁移。应用版本8/0.0.8-a3.3-backup，保持org.inkweft.app.a0.insertion。固定开发签名、页面移动/删除恢复、自动识别和PDF仍是后续独立工作，37AX与用户设备验收状态不变化。
