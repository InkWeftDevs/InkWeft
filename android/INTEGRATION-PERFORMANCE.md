# 集成性能与资源验证

本轮 N2 使用合成资料，不使用或上传平板私人笔记。当前报告仍在收口，最终构件和重复测量见 `CURRENT-STATUS.md`。全部绝对耗时来自 debug 配置，不是产品性能承诺。

## 可重复样本

`IntegratedPerformanceTest` 固定命名 UUID、轨迹、颜色和材质种子；每次保存内容 SHA-256、实际点数及对象数。样本均在现有作者格式预算内。

|样本|笔划|采样点|其他内容|
|---|---:|---:|---|
|普通笔记|20|640|单页|
|密集铅笔|600|19200|单页、固定石墨种子|
|局部擦除|120|3840|每笔一个固定局部遮罩|
|混合对象|80|2560|8 个文本对象；对象另存摘要|
|PDF 批注|1|32|1 页本地生成 PDF，记录源文件摘要|
|导图|0|0|64 张卡、64 个节点，记录布局摘要|

绘制探针分开记录解码、第一张完整预览、精细帧、120 次热绘制及可得内存。混合页的笔迹计时与对象绘制分开，不能把笔迹耗时称为完整混合页面耗时。PDF 探针不代表大 PDF 导入性能。

`WorkflowPerformanceTest` 使用同样规模的 600 笔合成铅笔页，通过真实文档会话补测数据就绪、完整预览、精细帧、热重开、导图开关及擦除提交／可见更新。擦除命令由仓库提交，不能称为触笔到像素延迟。

## 比较与原始证据

测试环境固定为本机 MuMu `InkWeft-Test`，Android 12、1920×1200、240 dpi、字体缩放 1.0。记录实际刷新率；同模式前后各重复 3 次，取中位数，保留每次原始 JSON。模拟器结果不替代 vivo 平板的真实压力、倾斜、掌拒或持续热负载结果。

本机归档：`E:/Inkweft/archives/2026-09-28/Integrated-Mindmap/`。前置样本基线为该目录 `baseline-workspace.apk`；它已包含首批 N1/N3，尚未加入本轮资源记账，不应标为原封不动的 v34 正式包。候选均保存独立摘要。

首次资源版本的 3 次中位数显示：密集铅笔精细帧从 1139.514 ms 变为 1424.496 ms，热绘制 P95 从 1.612 ms 变为 0.880 ms。不能只报告后者。针对逐瓦片记账开销，已改为每渲染引擎批量登记两种分配；最终复测待收口，首次回退数据保留。

## 资源边界

- `RenderResources` 对同一分配按引用所有者登记，在 CACHE、IN_FLIGHT、ACTIVE、LIVE_INK 中只计一次；类别与角色是同一总量的不同视图，不能相加。
- 128 MiB 是已登记渲染分配的软准入预算，覆盖历史位图、精细／预览输出、铅笔 RGBA 瓦片与浮点沉积场、PDF、图片及 OCR 源位图。活动输入优先；它不是进程 PSS 或 GPU 内存上限。
- 作者模型、字体／识别模型、驱动内部资源及未登记的瞬时小缓冲不冒充已覆盖。Java 堆、native 堆与 PSS 另报；不可得 GPU 内存为 `null`。
- 低内存清理释放可回收缓存引用，活动帧不手动 recycle。后台过期任务沿用代次校验并取消；渲染派生物不进入作者备份。
- 比较缓存只适用于不可变笔划实例，仍检查采样、外观及擦除遮罩。局部擦除产生的新对象不能命中旧结果。

## 指标解释

原始窗口帧时长用于计算 P50/P95 和超过实际刷新周期的帧数；GPU duration 不是 GPU 内存。`/proc/self/task` 可用时记录 UI／RenderThread CPU tick 差值，按系统时钟频率换算；不可读则为 `null`。这些进程累计 CPU 数字不等于某一帧的超期原因。

方法参考 [Android 帧与启动指标](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics) 和 [Android 内存管理](https://developer.android.com/topic/performance/memory)。本轮不引入会影响作者数据的磁盘预览，不减少采样，不调整阈值来制造通过。
